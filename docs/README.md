# 📚 Documentation
>YnFOR

Bienvenue dans le dossier docs/ du projet YnFOR.  
Cet espace regroupe l’ensemble des documents techniques, organisationnels et opérationnels nécessaires au bon fonctionnement du projet.

---

🗂️ Contenu du dossier

Ce dossier contient (ou contiendra) les documents suivants :

- CONVENTIONS.md — Conventions de code, branches, commits et normes internes  
- ARCHITECTURE.md — Structure technique du projet (si ajouté)  
- GUIDES/ — Guides d’utilisation, tutoriels, procédures internes  
- API/ — Documentation API (si applicable)    
- StyleGuide.md — Normes graphiques et design system (optionnel)  

---

🎯 Objectif du dossier

Le dossier docs/ a pour but de :

- Centraliser toute la documentation du projet  
- Faciliter l’onboarding des contributeurs  
- Assurer une cohérence technique et organisationnelle  
- Servir de référence pour les décisions et évolutions futures  
- Maintenir un niveau professionnel et structuré pour YnFOR  

---

🧭 Organisation recommandée

Pour un projet propre et évolutif, voici une structure conseillée :
```text
docs/
 ├── README.md
 ├── CONVENTIONS.md
 ├── ARCHITECTURE.md
 ├── StyleGuide.md
 ├── API/
 │    └── index.md
 └── GUIDES/
      ├── installation.md
      ├── utilisation.md
      └── contributeurs.md
```

---

🛠️ Mise à jour de la documentation

Avant chaque release ou évolution majeure :

1. Vérifier que les documents sont à jour  
2. Mettre à jour la ROADMAP  
3. Ajouter les changements dans le CHANGELOG  
4. Documenter les nouvelles fonctionnalités  
5. Harmoniser les conventions si nécessaire

🤝 Contribution

Les contributions à la documentation suivent les règles définies dans :

- .github/CONTRIBUTING.md  
- .github/CODEOFCONDUCT.md  

Merci de maintenir une documentation claire, professionnelle et accessible.
